Multi-Modal, Multi-Hop, Multi-Threaded
Tool-Using MLLM Agent Benchmark

M³-Bench is a lightweight benchmarking and analysis suite around the Model Context Protocol (MCP). It orchestrates 27 real MCP servers, drives multi-modal LLMs to solve 211 image-grounded tasks, and evaluates the trajectories at three granularities: step, call, and final answer.

Why It Matters

Real MCP Tools, Not Simulated APIs

Most tool-use benchmarks either hand-craft a small simulated tool set or score the agent by text patterns alone. M³-Bench instead boots real MCP servers and lets the model actually call them: Amazon catalog lookup, Wikipedia, Google Maps, NASA APOD, yfinance, Ultralytics YOLO detection, barcode scanning, OCR, Excel, PowerPoint, and many more.

A single task may need the agent to read a shelf photo, detect the products with YOLO, search each one on Amazon to get a price, sum them in a math tool, and return the total — all threaded across multiple servers and parallel calls.

The Three M's

Multi-Modal · Multi-Hop · Multi-Threaded

Every task is designed to stress all three axes at once, so a model cannot get away with single-tool recall or text-only reasoning.

① Multi-Modal

Each task ships with an image. The agent must visually parse shelf photos, labels, barcodes, OCR targets, or scene content, then feed that perception into the tool chain.

② Multi-Hop

Tool calls span several servers. Typical chains: YOLO → Amazon → Math; OCR → Wiki → Weather; Barcode → OpenLibrary → Review summary.

③ Multi-Threaded

Within a single reasoning step the agent often issues several parallel calls (e.g. three Amazon queries at once for three detected items), then synthesizes the joined result.

Three-Layer Evaluation

Step · Call · Final Answer

We do not score a single scalar. Each prediction is evaluated at three granularities, so weaknesses (e.g. correct plan but wrong final answer) are visible.

① Step-level

Trajectory quality against GT steps: recall, precision, avg similarity, step coherence, order consistency, merge purity. Runs in evaluate_trajectories.py.

② Call-level

Per-call classification into correct / partially-correct / hallucinated / redundant categories. Aggregated pies via evaluate_calls.py.

③ Final-answer

Task completion and information grounding of the final reply against the GT answer, scored by evaluate_final.py.

2026-05 Update

From Paid DINO-X-MCP to Local YOLO

The original benchmark used DINO-X-MCP, a cloud detection service with a paid API key and per-call quota. This made every rerun both expensive and flaky. As of May 2026 we ship a drop-in replacement called mcp-yolo.

Same tool surface

Identical tool names: detect-all-objects and detect-objects-by-text. Identical payload shape. No task JSON needs editing.

Local, zero-quota

Backed by Ultralytics YOLO (closed-set) and YOLO-World (open-vocabulary text-prompt detection). Runs fully on your machine — no cloud key, no rate limit, no bill.

Graceful fallback

The old dinox-mcp entry is still present in mcp_servers.json with "disabled": true, so older papers that cite the DINO-X chain can still be reproduced by flipping the flag.

Verified in CI

tools/functional_test_mcp_servers.py probes every enabled server with a real tool call; mcp-yolo passes on the sample media/00000000.png with detection results.

Upshot. Benchmarks should be reproducible without credit cards. Swapping DINO-X for YOLO keeps the task distribution fixed while removing an external dependency that can silently change or expire.
Quick Start

Run M³-Bench in a Few Commands

Requirements: Python 3.11, Conda, Node.js (for JS-based MCP servers), optional CUDA, and API keys in .env for commercial endpoints (OpenAI / Anthropic / Google / xAI / DeepSeek / Zhipu, plus the few MCP servers that need Amazon, NASA, Unsplash, or Reddit credentials).

① Install deps

conda create -n mcp_app python=3.11 -y
conda activate mcp_app
pip install -r requirements_pip.txt

# Node-based MCP servers
(cd servers/tmdb-mcp-server && npm i && npm run build)
(cd servers/mcp-server-nationalparks && npm i && npm run build)
(cd servers/metmuseum-mcp && npm i && npm run build)
(cd servers/okx-mcp && npm i && npm run build)
(cd servers/hugeicons && npm i && npm run build)
(cd servers/math-mcp && npm i && npm run build)
(cd servers/healthcare-mcp-public && npm i)

② Smoke-test every server

python tools/test_mcp_servers.py
# Initialization handshake per server

python tools/functional_test_mcp_servers.py
# One real tool call per server, checks isError and preview

27 servers report OK end-to-end on a clean checkout.

③ Run the benchmark

bash scripts/benchmark_fuzzy.sh
# -> results/<model>_test_mcp_fuzzy.json

④ Evaluate at three granularities

bash scripts/evaluate_step.sh         # trajectory quality
bash scripts/evaluate_call.sh         # call classification
bash scripts/evaluate_final_answer.sh # task completion
